# 심사위원 예상 질문과 근거 (judge_qa)

수치는 `outputs/presentation/12_key_numbers.json`, 근거 코드는 괄호 안 파일.

1. **왜 최근접 거리가 아니라 E2SFCA인가?** — 최근접 거리는 수요 경쟁을 무시한다. E2SFCA는
   `R_j = S_j / Σ W(d_ij)P_i`, `A_i = Σ W(d_ij)R_j`로 시설을 함께 쓰는 고령인구를 반영한다. 실제 두 순위의 상관은
   ρ = 0.23이며, 분당동은 최근접 1위지만 E2SFCA 36위(주변 수요 많음)다 (`accessibility.py`,
   `accessibility_method_comparison.csv`).
2. **거리는 어떻게 쟀나?** — OSM 보행망 최단경로(m). 점은 최근접 노드에 스냅하고 스냅 거리를 더한다. 직선거리
   E2SFCA와의 순위 상관 0.88 (`network.py`).
3. **공급량 정의는?** — 의료: 병상·의사수가 원자료에 없어 시설 1개=1(proxy, 종별 가중은 민감도용).
   복지: 시설이용형(주야간보호·단기보호) 정원(명). 방문형 급여는 거리 개념이 맞지 않아 제외.
4. **E2SFCA 구현이 맞다는 근거는?** — 공급 보존 성질 `Σ P_i·A_i = Σ(도달 가능 시설) S_j`를 실제 데이터와 무작위
   입력 모두에서 테스트하고, 손계산 예제와 대조 (`tests/test_unit_methods.py`, `test_pipeline.py`).
5. **MVI 식과 이유는?** — `MVI = Need × (1 − Access)`(예선 정의). 곱이라 수요와 결핍이 동시에 클 때만 높다.
   가중합 형식과의 순위 상관 0.99, Need 단독과 0.94 — 순위는 Need 영향이 크다는 점을 숨기지 않는다 (`mvi_ablation.csv`).
6. **상위 지역은 왜 높나?** — `mvi_components.csv`에서 원자료→정규화→MVI를 추적. 1위 성남동: Need 0.80, 종합 Access 0.14,
   가장 약한 요소 대중교통.
7. **공간적으로 유의하게 모여 있나?** — Global Moran I = 0.273, 999회 순열 p = 0.004. Local Moran HH·유의 6개 동.
   Queen 가중치는 섬 0, 연결요소 1, 대칭 검증 (`spatial_summary.json`).
8. **Robust Hotspot은 어떻게 정했나?** — MVI 가중치 3 × 거리감쇠 3 × 결합형식 2 × 정규화 2 = 36 시나리오마다
   접근성→MVI→LISA를 재계산, HH·유의 비율 ≥ 0.8인 4개 동만 '안정'. primary 한 번만 보면 hotspot인 성남동·신흥1동·하대원동은
   '불안정'으로 분리 (`robustness_report.json`).
9. **MCLP가 정말 최적인가?** — CBC Optimal 확인, 작은 예제에서 완전탐색과 일치 테스트. k=5 커버 0.865,
   취약수요 상위 동 우선 0.621(+24.4%p), 탐욕 0.858, 무작위 0.345 (`baseline_comparison.csv`).
10. **같은 최적값이 여러 개면?** — 1단계 최적값을 제약으로 고정하고 '커버 수요까지 평균거리' 최소화 2단계로 결정적 선택.
11. **정책 A/B/C는 이름만 다른가?** — 목적함수가 다르다: A 취약커버 최대, B 최소 구 커버 최대(maximin), C A와 같은
    커버 이상을 최소 vehicle-km. 결과: 커버 A 0.865 ≥ B 0.858, 최소 구 커버 B 0.827 ≥ A 0.774, 운행 C 17.3km < A 21.5km.
    최적성에서 나오는 부등식을 테스트로 검증하며 선정 정류장도 다르다(Jaccard A-B 0.25).
12. **정책 C는 어떻게 풀었나? 근사 아닌가?** — 구별 후보 8개로 축약(MCLP·Maximin 최적해 정류장 빈도순 우선) 후 3개 구
    부분집합 조합 1,677만 개를 완전탐색, 노선은 Held-Karp 정확 TSP. 축약 집합 내 정확해이며 전체 후보 전역최적은 주장하지
    않는다. 축약 후보가 A의 해를 포함하지 않을 수 있어(현재 데이터도 미포함) A의 해를 같은 거리로 따로 평가·비교하므로
    'C ≤ A 운행거리'는 보장된다. 완전탐색 코드는 작은 예제의 독립 브루트포스와 일치함을 테스트한다. 예산별 Pareto 9점 모두 비지배.
13. **노선거리는 현실적인가?** — OSM 차량망(일방통행) 최단경로, 구 보건소 거점. 속도 20km/h·정차 3분·최대 순환 90분은
    가정이며 What-if에서 바꿀 수 있다.
14. **LLM이 틀린 말을 하면?** — LLM 입력은 JSON Schema로 검증된 근거뿐. 출력의 숫자는 붙은 KPI 라벨·단위로 해당 필드와
    대조(값 뒤바꿈 탐지), 지역명은 원자료 어휘, 정책명·지표·인과 표현 검사. 실패 시 1회 재생성 후 템플릿.
    gemma3:4b 실측에서 '종합 접근성 값을 대중교통 접근성이라고 쓴' 오류를 실제로 차단했다(`llm_grounding_check.json`).
    단위가 붙은 숫자 변조(21.47km→12.5km), 다른 정책 값 끼워넣기, '때문입니다'·'탓' 같은 인과 변형, '채택해야' 같은 권고 표현 등
    적대적 사례를 `tests/test_grounding.py`로 고정 검증한다.
15. **다른 PC에서 재현되나?** — 버전 고정 requirements, seed 고정, 결정적 동점 해소, OSM·지오코딩 결과 버전관리.
    `run_pipeline.py --validate`가 새로 계산해 저장소 결과와 파일 단위로 비교하고, `scripts/preflight.py --package`가
    제출 ZIP을 새 폴더에 풀어 테스트·파이프라인·데모를 다시 실행한다.
